# ice-web-client · MG400 融冰终端模拟器

用浏览器模拟「主控机柜」，与 **MG400 远程地线融冰控制系统操作平台**做 TCP 对接联调。没有硬件时，用它代替铁塔现场设备：平台下发动作命令 → 网页上点「到位」→ 终端把状态帧回给平台 → 平台继续下一步。

- 单容器部署（Docker，`linux/amd64` + `linux/arm64`）
- 镜像：`ghcr.io/xushier/ice-web-client`
- 内网工具，HTTP 无鉴权

## 功能

- **服务器配置**：IP / 域名 + 端口，断线自动重连（带退避），上报周期可调。
- **多模块同屏**：一个模块一条独立 TCP，两塔协同任务可在一个页面里同时操作。
- **模块建模**：铁塔号（仅界面区分）、模块 ID（写入帧 ID 字段，bit0 = 大小号侧）、**设备自由勾选 + 顺序可调**（新建时排好，之后也能拖拽）。
- **设备**：接地刀闸、融冰刀闸、融冰锁、选相刀闸（0~N）、电池活化。
- **三态按钮**：每台设备左「初始态」/ 中「动作中」/ 右「融冰态」，绿 / 橙 / 红对应危险等级；卡片顶部可一键切「初始态 / 融冰态」。
- **人工到位**：平台命令到达后卡片出现指令条，点「已到位」即改状态并立即上报 `0x10`。
- **自动模式**：合闸 → 合闸到位、分闸 → 分闸到位（1:1 映射），延时秒数可配，多动作可串行 / 并行。
- **帧监视**：停靠在右侧、与页面联动（不遮挡模块卡片），实时收发 hex + 逐位语义解析，未知帧高亮并展开原始字节。
- **帧构造器**：选类型、勾位、填字段或直接粘整帧 hex 发送。

## 协议要点

帧格式（8 字节开销）：

```
5A 47 | LEN(=3+数据长) | ID(2, 高字节先发, bit0=大小号侧) | 类型 | 数据(n) | CRC16-MODBUS(低字节在前)
```

| 类型 | 方向 | 说明 |
| --- | --- | --- |
| `0x00` | 平台→终端 | 远端操作命令（2 字节位图，唯一的下行动作帧） |
| `0x01` | 终端→平台 | 命令响应 |
| `0x05` | 终端→平台 | 上线注册（协议未定义；实测平台回心跳，可关） |
| `0x10` | 终端→平台 | DI 状态（60s + 变化即发，兼心跳） |
| `0x11` | 平台→终端 | 心跳应答 |
| `0x20` | 终端→平台 | 直流供电状态（18 字节，连接后 1 次 + 每 60 分钟） |
| `0x30` | 终端→平台 | 环境状态（本期只解析，不上报） |

**命令帧与状态帧的位布局不同**，代码里是两张表（`src/protocol/bits.ts`）：

```
0x00 命令  高字节:  -- -- -- -- | 冰合 冰分 锁闭 锁开
           低字节: 地合 地分 选1合 选1分 选2合 选2分 活化 --
0x10 状态  高字节: 备 备 网络错 冰合 冰分 锁闭 锁开 地合
           低字节: 地分 选1合 选1分 选2合 选2分 模式 电量[1:0]
```

例：接地刀闸在命令帧是 `Byte1 b7/b6`，在状态帧是 `Byte0 b0`（合）+ `Byte1 b7`（分）。混用会导致平台读到错误状态。

**电池活化**（现场指令已确认）：低字节 b1 置 1 为活化开，数据区全 0 为活化关。

```
活化开  #1：5A 47 05 00 01 00 00 02 72 24
活化关  #1：5A 47 05 00 01 00 00 00 F3 E5
```

**动作中状态**在 `0x10` 里没有对应位（合、分两位都为 0），所以「动作中」只体现在界面与本地状态，平台侧看到的是「既非合位也非分位」。

**活化状态上报**：协议文档没有给 `0x10` 定义活化位，但命令帧里活化就是低字节 b1（`0x0002`）。因此默认把 `0x10` 低字节 **b1 作为活化状态位**（开=1、关=0），电量档降为 b0 一位（PDF 本身也注明「建议平台不要使用」电量档）。若现场平台判读的是 b0，可在「服务器与上报参数 → 0x10 活化状态位」切换；选 `none` 则恢复 4 档电量、不上报活化。

## 快速开始

```bash
docker run -d --name ice-web-client \
  -p 8080:8080 \
  -v $(pwd)/data:/data \
  -e TZ=Asia/Shanghai \
  --restart unless-stopped \
  ghcr.io/xushier/ice-web-client:latest
```

或 `docker compose up -d`（见 `docker-compose.yml`）。打开 `http://<host>:8080`：

1. 点左上角「未配置服务器」→ 填平台 IP 与端口 → 保存。
2. 「新建模块」→ 填铁塔号与模块 ID（与平台配置一致）→ 勾选设备、调整顺序 → 创建并连接。
3. 需要多塔协同时，再建一个模块即可（各自独立连接）。
4. 设备顺序可拖拽调整，与平台的流程顺序对齐。
5. 平台下发命令后，卡片出现指令条：点「已到位」，或开自动模式；也可以直接点三态按钮模拟过程。

数据落在容器 `/data`：`config.json`（服务器参数 + 模块 + 状态）、`logs/ops-YYYY-MM-DD.ndjson`（操作流水）。

## 本地开发

```bash
npm install
npm run dev:server   # 后端 :8080（DATA_DIR 默认 ./data）
npm run dev:web      # 前端 :5173，/api 与 /ws 已代理到 8080
npm test             # 协议单测
npm run typecheck
npm run smoke        # 端到端冒烟（内置假平台 + 真实服务进程）
npm run build && npm start
```

没有真实平台时可以用模拟平台：

```bash
node tools/mock-platform.mjs --port 4000
# 终端里按 g = 接地分闸，G = 接地合闸，i/I = 融冰合/分，l/L = 闭锁/开锁，j/k = 选相1 分/合
```

然后把服务器地址指向 `127.0.0.1:4000` 即可全流程自测。

## 目录

```
src/protocol/   纯函数协议层：CRC、组帧/拆帧、双位表、语义解析
src/core/       会话引擎：模块连接、重连退避、上报调度、命令队列、自动模式、持久化
src/server/     Fastify：REST + WebSocket + 静态站点
src/web/        React 界面（模块卡片、帧监视、帧构造器）
tests/          协议单测（含现场帧逐帧断言）
tools/          本地模拟平台
scripts/        smoke.mjs 端到端冒烟
```

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 服务器参数 + 全部模块快照 |
| PUT | `/api/server` | 更新服务器/上报参数 |
| POST | `/api/modules` | 新建模块（`devices` 决定设备与顺序） |
| PATCH | `/api/modules/:id` | 改名称/ID/设备/顺序/遥测 |
| DELETE | `/api/modules/:id` | 删除模块 |
| POST | `/api/modules/:id/{connect,disconnect,reconnect}` | 连接控制 |
| POST | `/api/modules/:id/devices/:key` | `{state}` 置设备状态 |
| POST | `/api/modules/:id/preset` | `{preset:"initial"\|"melt"}` 一键初始/融冰态 |
| POST | `/api/modules/:id/pending/:pid` | `{action:"confirm"\|"dismiss"}` |
| POST | `/api/modules/:id/telemetry` | 遥测量 |
| POST | `/api/modules/:id/report` | 立即上报 `0x10`（可带 `0x20`） |
| POST | `/api/modules/:id/send` | `{hex}` 或 `{type,dataHex}` |
| GET | `/api/frames` | 历史帧 |
| GET/POST | `/api/config/export` `/api/config/import` | 配置迁移 |

`/ws` 推送 `state` / `frames` / `frame` 事件。

## 已知限制

- **选相刀闸 > 2**：协议只定义 1、2 两组合/分位，第 3 个起允许创建但标注「无位」，不参与 `0x10`。
- **空调 / 环境**：`0x02`、`0x03`、`0x30` 只解析展示，不上报。
- **电池电压**：协议单位 0.1V，界面按 1 位小数显示。
- **CRC**：默认按 CRC-16/MODBUS 正确计算；实测平台不校验，若要复现问题可在设置里改成填 `00 00`。
- **同 ID 只允许一条会话**：平台对同一模块 ID 只保留一条连接，后连的会在收到第一帧后被断开（实测 ID 11/12/13 表现如此，未知 ID 不受限）。同时开两个终端实例时注意错开 ID。
