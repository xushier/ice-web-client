# MG400 融冰终端模拟器（ice-web-client）设计方案

- 版本：v1.1（已实现并上线，对应仓库 `main`）
- 协议依据：《MG400 远程地线融冰控制系统通讯协议》V0.0.1（2025-07-08）+ 《融冰指令生成器》位表（更精确）
- 交付形态：单容器 Web 应用（Docker，amd64 + arm64），镜像推 GHCR

> 本文中「必须 / 应当 / 可以」按 RFC 2119 语义使用。

---

## 1. 定位与边界

平台下发 `0x00` 动作命令 → 终端（本模拟器）解析出「哪台设备、哪个动作」→ 操作员在网页上点「到位」→ 终端回 `0x10` 状态帧 → 平台判定该步完成。

**做**：终端侧的全部模拟能力（连接、上报、命令应答、人工/自动到位、帧监视、帧构造）。
**不做**：平台侧改造、任务编排（顺序由平台决定）、空调与环境上报、鉴权。

## 2. 协议实现

### 2.1 通用帧结构

| 偏移 | 字节 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0x00 | 2 | 帧头 | `5A 47` |
| 0x02 | 1 | 长度 | `3 + 数据区长度`（ID 2 + 类型 1 + 数据 n），不含 CRC |
| 0x03 | 2 | 模块 ID | 高字节先发；12bit，**bit0 = 大小号侧**（0 小号 / 1 大号） |
| 0x05 | 1 | 类型 | 见 2.2 |
| 0x06 | n | 数据区 | 按类型定义 |
| 0x06+n | 2 | CRC | CRC-16/MODBUS，从帧头算起，低字节在前 |

### 2.2 帧类型

| 类型 | 方向 | 名称 | 数据长度 | 处理 |
| --- | --- | --- | --- | --- |
| 0x00 | 平台→终端 | 远端操作命令 | 2 | 核心：解析动作位 |
| 0x01 | 终端→平台 | 命令响应 | 1 | 收到 0x00 立即回 `00` |
| 0x02 / 0x03 | 双向 | 空调命令/响应 | 1 | 仅解析 |
| 0x05 | 终端→平台 | 上线注册（文档未定义） | 2 | 可开关，默认连接后发一次 `FF FF` |
| 0x10 | 终端→平台 | DI 状态 | 2 | 核心：状态上报，60s + 变化即发 |
| 0x11 | 平台→终端 | 心跳应答 | 1 | 仅解析 |
| 0x20 | 终端→平台 | 直流供电状态 | 18 | 连接后 1 次 + 每 60min |
| 0x21 | 平台→终端 | 供电应答 | 1 | 仅解析 |
| 0x30 / 0x31 | 双向 | 环境状态/应答 | 16 / 1 | 仅解析，不上报 |

### 2.3 `0x00` 命令位（高字节先发）

| 位 | 含义 | 生成器标识 |
| --- | --- | --- |
| Byte0 b3 | 融冰刀闸 合闸 | C1 |
| Byte0 b2 | 融冰刀闸 分闸 | C2 |
| Byte0 b1 | 融冰锁 闭锁 | D1 |
| Byte0 b0 | 融冰锁 开锁 | D2 |
| Byte1 b7 | 接地刀闸 合闸 | A1 |
| Byte1 b6 | 接地刀闸 分闸 | A2 |
| Byte1 b5 | 选相刀闸 1 合闸 | B1 |
| Byte1 b4 | 选相刀闸 1 分闸 | B2 |
| Byte1 b3 | 选相刀闸 2 合闸 | B3 |
| Byte1 b2 | 选相刀闸 2 分闸 | B4 |
| Byte1 b1 | 电池活化 开启 | E1 |
| Byte0 b7~b4 / Byte1 b0 | 保留 | — |

**电池活化关 = 数据区全 0**（生成器 E9 / 急停 C9 同为零值帧）：

```
活化开  #1：5A 47 05 00 01 00 00 02 72 24
活化关  #1：5A 47 05 00 01 00 00 00 F3 E5
```

### 2.4 `0x10` 状态位（高字节先发）

| 位 | 含义 |
| --- | --- |
| Byte0 b5 | 网络错误（1=错误） |
| Byte0 b4 / b3 | 融冰刀闸 合到位 / 分到位 |
| Byte0 b2 / b1 | 融冰锁 闭锁到位 / 开锁到位 |
| Byte0 b0 | 接地刀闸 合到位 |
| Byte1 b7 | 接地刀闸 分到位 |
| Byte1 b6 / b5 | 选相刀闸 1 合/分到位 |
| Byte1 b4 / b3 | 选相刀闸 2 合/分到位 |
| Byte1 b2 | 控制模式（1=本地 / 0=远程） |
| Byte1 b1~b0 | 电池电量粗略值 4 档（0/25/50/75%） |
| Byte0 b7 / b6 | 备用 |

> **两张表不能混用**：接地刀闸在命令帧是 `Byte1 b7/b6`，在状态帧是 `Byte0 b0` + `Byte1 b7`；融冰锁命令帧 `b1/b0`、状态帧 `b2/b1`。

### 2.5 `0x20` 直流供电（18 字节，16 位无符号，高字节先发）

电量%、电池电压(0.1V)、负载电压(0.1V)、负载电流(0.01A)、光伏电压(0.1V)、光伏电流(0.01A)、负载/充电状态、故障高/低 16 位。

## 3. 设备状态模型

每台设备三列：**左 = 初始态（绿）· 中 = 动作中（橙）· 右 = 融冰态（红）**。

| 设备 | 左（初始态） | 中（动作中） | 右（融冰态） |
| --- | --- | --- | --- |
| 接地刀闸 | 合闸到位 | 分闸中 / 合闸中 | 分闸到位 |
| 融冰刀闸 | 分闸到位 | 合闸中 / 分闸中 | 合闸到位 |
| 融冰锁 | 闭锁到位 | 开锁中 / 闭锁中 | 开锁到位 |
| 选相刀闸 | 分闸到位 | 合闸中 / 分闸中 | 合闸到位 |
| 电池活化 | 活化关闭 | — | 活化开启 |

中间按钮的文案随当前位置变化：从左侧往右动显示「分闸中 / 开锁中」，从右侧往左动显示「合闸中 / 闭锁中」。

**动作中在 `0x10` 里没有位**（合、分两位都置 0），符合现场「既非合位也非分位」的表现。

默认（新建模块）状态 = 每台设备的左列：接地合、选相分、锁闭锁、融冰分、活化关。

## 4. 会话与上报

```
连接 → 0x05(可关) → 0x10 → 0x20 → 启动 60s / 60min 定时器
状态变化 → 80ms 去抖后立即发 0x10
收到 0x00 → 回 0x01 → 生成待动作（冲突位置位时标记冲突、不自动执行）
       ├ 人工：点「已到位 / 忽略」
       └ 自动：延时 N 秒（可串行/并行）后置位并上报
断线 → 退避重连（0.8s→1.6→…→30s）；稳定在线 15s 才重置退避计数
```

「创建后立即连接」在服务端建模块时直接发起连接，不依赖前端二次点击。

## 5. 架构

```
浏览器（React SPA） ──HTTP/WS──> Node 服务（唯一状态源） ──TCP×N──> 操作平台
                                      └── /data：config.json + 逐日操作日志
```

- 前端：React 19 + Vite + Tailwind v4（手写 ui 原语，无组件库）
- 后端：Fastify + ws + `net`，esbuild 打单文件 `dist/server.cjs`
- 状态：服务端进程内单一状态机；浏览器只发意图，服务端广播全量快照（60ms 合并）
- 帧日志：服务端环形缓冲每模块 400 条，页面刷新不丢

## 6. 界面

- **顶栏**：服务器地址、实时通道状态、在线数、新建模块、全部连接/断开、帧监视（可停靠）、帧构造器
- **左侧栏**：模块列表（可折叠，状态点 + 塔号 + ID），折叠后只留状态点
- **主区**：模块卡片网格。卡片 = 头部状态 + 指令条 + 设备三态按钮（可拖拽排序）+ 遥测 + 快捷上报
- **右侧「帧监视」**：停靠式侧栏（非弹窗），实时帧列表 + 展开解析 + 帧结构速查；打开时压缩主区而不是遮挡卡片
- **帧构造器**：类型选择 + 位勾选 / 字段填写 / 整帧 hex，实时预览最终帧与语义摘要

## 9. 验证

- 单测 32 条：CRC 向量、组帧断言（含现场帧 `5A470500010000027224` / `...F3E5`）、粘包/半包/噪声同步、双位表差异、动作中编码、三态按钮顺序、默认排序
- 端到端 `npm run smoke`：假平台 + 真服务进程，覆盖 0x05/0x10/0x20 上报、命令 ACK、人工到位、自动模式、未知帧、活化开关、创建即连接、设备顺序
- 真实平台：连接、上报、心跳应答全通（详见附录 A）

## 10. 已知限制

- 选相刀闸 > 2 无状态位（标注「无位」）
- 空调 / 环境帧只解析不上报
- 电池电压精度 0.1V
- 同一模块 ID 平台只保留一条会话（后连者收帧后被断开）

## 附录 A：现场联调记录

```
→ 0x05 5A 47 05 00 0D 05 FF FF E1 04        上线注册
→ 0x10 5A 47 05 00 0D 10 0D 53 B5 DD        DI 状态
→ 0x20 5A 47 15 00 0D 20 ... F6 A9          供电状态
← 0x11 5A 47 04 00 0D 11 00 82 21 ×N        平台对每一帧回心跳
```

观察结论：

1. 平台**不要求**先注册，收到任何合法帧即回 `0x11`；`0x05` 保留为可关开关。
2. 平台**不校验** CRC（我方 CRC 本来就是正确值）。
3. 被动连接（不发帧）可长期保持；一旦某 ID 已有会话在线，新连接在收到第一帧回复后会被断开。
